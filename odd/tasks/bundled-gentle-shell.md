# Bundled Gentle Shell: a hermetic install that never uses the user's tools
Objective: install and run Gentle Shell as one self-contained product (its own pinned Pi, Node, pnpm and Go) through the web installer and through Gentle Shell itself, without detecting, running or changing the user's own tools.
Branch: feat/bundled-gentle-shell (design approved; one work-unit commit and PR per task). Delivery: ask-on-risk, chained PRs per task. Test runner: `node --experimental-strip-types --test tests/<file>.test.ts`; Windows-native tests in the `installer (windows-latest)` lane (0 skips).

## Specs
- S1. Maintainer vision (verbatim): "el instalador web tiene que instalar de la misma manera que lo hace GentleShell, ¿bien? Punto. El tema es que tiene que instalarlo como un empaquetado. Total empaquetado. O sea, vos ejecutas GentleShell, ejecutas GentleShell, no el PID [Pi] del usuario. ... Es más, si vos ejecutas GentleShell en la terminal, automáticamente te aísla todo y lo hace todo aparte. El único problema es que si Pi se actualiza o cosas por el estilo, van a perder esas actualizaciones hasta que nosotros lo metamos." and "Nuestra versión de PNPM para instalar, nuestra versión de Go para instalar, todo lo nuestro y listo, y no jodemos con las cosas del usuario".
- S2. Decision "Node embebido (recomendado)": Gentle Shell carries its own pinned Node in a private prefix, as Pi's official installer does (pi.dev/install.sh downloads Node to ~/.local/share/pi-node and runs `npm ci` from a per-version lockfile). The Node launcher (bin/gentle-shell.mjs) is kept. Pi's bun binary is a later phase, only after a spike (ffi-rs under bun, process.execPath refactors, launcher port).
- S3. Decision "Lockfile + nuestro pnpm (recomendado)": each Gentle Shell release publishes a frozen lockfile for gentle-pi + the exact Pi; the installer and `gentle-shell upgrade` run our pinned pnpm with `install --frozen-lockfile` into `versions/<shell>-<pi>/`, with pnpm's store, cache, state and config inside the prefix. Prebuilt per-platform tarballs are a possible later phase.
- S4. Decision "Migrar con una confirmación (recomendado)": an existing Gentle Shell installed globally with pnpm or npm (detected by installOwner) gets the new prefix, then one question to remove the old global gentle-pi with its own manager; the user's Pi is never touched; the isolated home ~/.gentle-shell/agent does not move; an `npm link` (owner null) is left as it is and named.
- S5. Decision "Redirigir a gentle-shell upgrade (recomendado)": inside Gentle Shell, `pi update` and `gentle-shell update` explain that Pi ships pinned with Gentle Shell and run (or offer) `gentle-shell upgrade`.
- S6. Layout (proposal, POSIX): `~/.gentle-shell/{agent/, runtime/node-<v>/, runtime/pnpm-<v>/, runtime/go-<v>/ (only for the main channel or a Windows source build), pnpm/{store,cache,state,config}/, versions/<shell>-<pi>/, current, bin/gentle-shell}`; `current` switches atomically (symlink on POSIX, pointer file on Windows); the previous version is kept for rollback (keep 2, like Claude Code). Windows: the same layout under the private folder the bootstrap already claims (%LOCALAPPDATA% then the %USERPROFILE% fallback), with the same ACL rules.
- S7. PATH: exactly one entry for `bin/gentle-shell` (POSIX: a symlink in ~/.local/bin when it is already on PATH, otherwise one marked line in the shell profile; Windows: the user Path in HKCU). `pnpm setup` is no longer used. self-uninstall removes only the marked line/entry it wrote.
- S8. Pi is exact: the launcher runs only the Pi inside `current` (no adjacent/PATH fallback in the bundled install); subagents inherit our Node and Pi (process.execPath + cli.js). Pi bumps ship as Gentle Shell releases (pin bump + CI gate); `gentle-shell upgrade` shows the bundled Pi version.
- S9. Isolation leaks to close: pi-pretty writes $HOME/.pi/agent/pi-pretty/fff ignoring PI_CODING_AGENT_DIR; gentle-ai state in ~/.pi/gentle-ai and ~/.gentle-ai; Engram setup through the user's npm. Runtime tools the agent uses for the user's work (git, gh, codegraph) stay the user's.
- S10. Removal: the installer's user-tool detection and reuse logic (user Node/npm/pnpm/Go probes, shim parsers, PATHEXT, Corepack/mise, persistence variants, globalBin pnpm rules, private PNPM_HOME decision, reused-folder notice, npm prefix configuration) is deleted once the bundled path ships; the download/verification of the pinned Node, pnpm and Go and the Windows private-folder claim are reused.
- S11. Windows Go: today the Windows Gentle AI binary is built from source in the postinstall (no signed Windows archive). Publishing a signed Windows Gentle AI binary in gentle-ai releases would remove Go from the Windows release path (cross-repo follow-up).
